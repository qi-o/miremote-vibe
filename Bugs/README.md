# Bugs 档案(v2.0 起启用)

每个 bug 一个文件,命名 `YYYY-MM-DD-主题.md`。五段式(参照 SayAll Bugs/ 制度):

```markdown
# 标题(现象一句话)

## 复现
- 环境/版本/步骤。

## 证据链(全部标注来源:真机实测/日志/受控实验)
- 逐条列证据;受控实验优先 A→B→A→B 交替(排除状态漂移)。

## 根因判定
- 归因到层(固件/驱动/系统/输入法/本仓库);若是本仓库缺陷,指出具体机制。

## 处置
- 修复内容或"记录为第三方边界";写明接受了什么代价/残留。

## 验证
- 自动化(python -m pytest + tests/smoke_gestures.py)/配方级/真机分级记录;
  真机项未做就写 deferred,不要写"应该没问题"。
```

规则:
- 错误结论**不删除**,在同文件追加"勘误(日期+实证)"——错误路径对后来者同样有价值;
- "上游经验引用"(如 SayAll 的发现)注明来源档案与日期;
- 修复没有真机验证的,保持 deferred 状态开放着,不许悄悄标 passed。
