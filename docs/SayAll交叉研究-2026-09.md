# SayAll(无线麦 Windows 版)交叉研究——及本项目 v2.0 的吸收清单

日期:2026-09-23。研究对象:[GetSayAll/remote-mic-app-windows](https://github.com/GetSayAll/remote-mic-app-windows)
(Rust + Tauri 2 + Vue 3,GPL-3.0,活跃维护;macOS 同源参考 HD838A/remote-mic-app)。
研究动机:两个项目硬件同源(小米 RC001/RC003)、问题域完全重合(按键救回/ATVV 语音/
输入法桥接),对方的工程档案公开且真机实证密度极高——是本项目之外唯一可比对的独立实现。

本文档同时是 v2.0 架构升级的设计依据:每条发现标注了[已吸收]/[部分吸收]/[记录不吸收(理由)]。

## 一、决定性技术发现(全部有对方真机证据背书)

### 1. WeType 实时语音的正确配方 —— 推翻本项目 live2 复盘的结论

本项目 2026-08 的 live2 复盘(docs/实时输入攻坚复盘-LIVE2_POSTMORTEM.md)结论之一是
"输入法在硬件键按住期间拒绝热键"。SayAll 的 2026-09-04 档案(Bugs/2026-09-04-wetype-zero-gap-injection.md)
用 A→B→A→B 交替受控实验给出了更精确的三层事实:

1. **WeType 不检查 LLKHF_INJECTED**(注入键可用;豆包才检查——豆包注入路线判死);
2. **零间隔批量 SendInput 和弦被拒**:一次调用批量提交 [LCtrl↓,LWin↓] = 无效和弦;
   **逐事件注入、两键边沿间隔 80ms** = 有效(两轮实验精确复现);
3. **F5 泄漏夹在和弦中间 = 整组和弦被拒**("额外按键"判定):日志抓到
   LCtrl↓→F5↓→LWin↓ 序列,WeType 拒绝;F5 全吞后同一配方立即通过。

即:本项目 v4 live 模式失败的真实根因是**注入形态(零间隔)+F5 泄漏**,不是"硬件键
按住"本身。live2 的"面板预开/时序错位"路线是在错误根因假设下的过度工程。

另两个配套事实:
- 系统默认录音设备 = CABLE Output 是对方测试契约的硬前提(本项目已建议在 WeType
  设置内固定设备,等效);
- 对方按住说话预设 = **左 Ctrl + 左 Win**(WeType 侧同样配置该热键)。

**[已吸收]** v2.0 新增 `wechat_rt` 实时模式:Ctrl+Win 按住式 + 80ms 间隔注入 +
F5 抑制器链头 bump(见下),复用本项目现成的 ATVV→CABLE 实时写入管线(live 基建)。

### 2. LL 钩子链头 bump(WeType 会插队)

WeType 自身会重装低级键盘钩子,插到别人钩子前面,导致吞 F5 的钩子被排到后面失效。
解法(VVC 技巧,SayAll 自 key_gate/key_suppressor 使用):**每会话开始 + 每 10 秒
定时"先挂新钩再卸旧钩"**,把自己 bump 回链头;先挂后卸消除空窗。

本项目 llhook.py 的 F5SuppressHook 单次安装后不再动——WeType 重装钩子后即被压到
后面,吞键失效。**[已吸收]** F5SuppressHook 增加 10 秒周期 bump + 会话开始即时 bump。

### 3. LL 钩子吞掉的事件不会再到达 Raw Input(含硬件事件)

对方 hw_swallow_probe 实证(2026-09-06):LL 钩子无条件吞掉遥控器 VK_LEFT 的 4 次
按压(DOWN/UP 共 8 硬件事件),Raw Input(INPUTSINK)观察到 **0** 个。

推论(对本项目):`leaksup.py` 的 arm/consume 模型(Raw Input 先武装、钩子再吞)
存在结构性竞态——武装信号依赖的 Raw Input 事件可能永远晚于钩子吞键。对方同文档
给出缓解:武装窗口放宽到 4 秒(遥控器任意按键活动后 4s 内的后续按压全部正确单响应,
>4s 的孤立首按仍泄漏一次,已记为边界)。

**[部分吸收]** v2.0 不引入完整 key_gate(见二.3 决策),但 leaksup 文档补记此边界,
v1.3 引入时的默认关闭策略被此发现二次确认。

### 4. RC003 在 Windows 上只有 TYPE=1 键盘设备,无 TYPE=2(HID)

对方全量枚举实证:RC003 只暴露一个键盘设备(HID 0x1812 接口),**没有任何可注册的
RAWHID(TYPE=2)设备**;返回(0xF1)/音量±(0x80/0x81)在键盘 VK、Consumer 页、
厂商 GATT 通知里全部零事件。CreateFile 直读键盘集合 = ACCESS_DENIED(管理员也无效)。

**[记录]** 与本项目 2026-08-24 全通道诊断结论("HID/RAWHID/GATT 零事件")独立互证:
Frida 注入 WUDFHost 是 Windows 上救回三键的唯一公开途径(本项目 tap4 路线正确且必要)。
对方因此在其应用内禁用了三键(不上 Frida 的边界),本项目的 tap4 是差异化能力。

### 5. "physicalize"是结构性 no-op

LL 钩子回调收到的 KBDLLHOOKSTRUCT 是**每钩子私有副本**,修改不跨钩子传播
(CallNextHookEx 转发原始记录)。"自家钩子清 INJECTED 标志再转发"不可能影响下游
钩子所见——ZSTDJan 的该技巧实为 no-op,其真正生效的是未接线的 Frida 版。

**[记录]** 解释了 open-voice-bridge RC003 版"ralt 改写"模式在真机上失败的原因;
本项目未来任何注入方案都不要走"钩子内改写标志"路线。

### 6. ConsentStore 麦克风注册表 = 输入法真开麦的铁证

`HKCU\...\CapabilityAccessManager\ConsentStore\microphone\NonPackaged` 下各 exe 的
LastStartTime/StopTime 精确到毫秒。判断"WeType 到底开没开麦"不再靠面板截图——
注册表时间戳是 ground truth(SayAll 把它做成了 wetype_revive.rs 观测模块)。

**[记录]** 本项目诊断工具箱注记;语音问题排查的第一证据源。

### 7. TSF 输入法激活必须会话级

线程级 ActivateAcceleration(TF_IPPMF_FORSESSION 未置位)会让 WeType 相关测试
全部假阴性(实际活动输入法不是 WeType)。对方 Round 2→3 的翻案正是踩了这个坑。

**[记录]** 任何涉及输入法的自动化测试脚本必须用会话级激活(0x20000000)。

### 8. TSF 激活有副作用边界

对方 2026-09-12 档案:按住说话快捷键路径里的 IME 会话级激活,在焦点为应用自身
WebView 且活动输入法≠WeType 时,触发整页重载。**[记录]** 若本项目未来做自动唤起,
注意"激活输入法"动作对焦点应用的副作用。

## 二、工程制度研究(对方真正的护城河)

### 1. Bugs/ 档案制度
每个 bug 一份根因文档:复现/证据链/根因判定/处置/验证五段式;受控实验用
A→B→A→B 交替排除状态漂移;写错的结论不删,追加"勘误"保留原貌。
**[已吸收]** 本项目新增 `Bugs/` 目录与同款五段式模板(README 见 Bugs/README.md)。

### 2. 测试手册的 deferred/passed 状态机
`Testing/Windows*.md` 每个用例标注真机验收状态;自动化通过≠真机通过;未验收项
一律 deferred,绝不宣称通过。**[已吸收]** v2.0 的真机相关新功能(wechat_rt 等)
在 Testing/手测清单.md 中标注 deferred,待真机验收后升级 passed。

### 3. 架构边界的成文约定(AGENTS.md)
- 核心层零平台依赖(对方 sayall-core 不 import Windows API);
- 提权能力独立 Helper 承载,主程序保持普通权限;
- DOWN/UP、订阅/退订、开始/停止一律成对;重试前先释放上轮资源;
- 会话带 generation 标识,旧回调不得污染新状态。
**[已吸收(裁剪版)]** 本项目新增 AGENTS.md,按 Python 单仓现实裁剪:
gestures/adpcm/协议解析保持纯逻辑零 IO(已是事实,固化为规则);tap4 提权注入
独立于主守护可独立运行(已是事实:backkey 独立模式)。

### 4. 结构化日志
对方 gatt_note 统一 `feature= action= phase= terminal_result= reason= elapsed_ms=`
键值行,可 grep 可统计。**[已吸收]** 新增 telemetry.py,新代码路径统一走结构化
日志,存量 print 不动(避免噪音 diff)。

### 5. 指数退避重连(纯逻辑)
2s 起步、×2、封顶 30s,成功即重置;实现为无 IO 纯类 + 单测。**[已吸收]**
reconnect.py(本项目语音守护断线重连原为固定 5s)。

### 6. 每键按住连发节律表(对齐 Mac 原版)
返回 50ms、方向/音量± 100ms、其余不连发;仅"只配单击"时启用。
**[已吸收]** gestures 派发器接入节律表作为默认值(显式 repeat_interval 仍可覆盖)。

## 三、明确不吸收的部分(及理由)

1. **完整 key_gate 吞键替换模型**(三族归因+武装+泄漏对冲):本项目 v1.3 的键位
   语义是"透传 + 附加动作"(文档明示,方向键原生作用于焦点窗口正是 vibe coding
   用法),改吞键替换是行为破坏性变更;且武装模型存在结构性首按泄漏(对方 4s 宽限
   只能缓解)。仅吸收其"身份映射对冲"思想:配置动作 == 原生键时跳过注入,消灭
   双响应(见 v2.0 gestures identity-offset)。
2. **Rust/Tauri 重写**:运行时形态不是本项目价值所在;Python 单文件可改性是明示卖点。
3. **minisign 更新器/NSIS 安装器**:发布形态按需再说。
