## 0. 项目背景与调研

**需求**：用小米蓝牙遥控器 2 Pro（RC003，约 65 元）在 Windows 上做 vibe coding——
躺沙发上语音指挥 AI 编程助手。

**调研结论（2026-08-24 上午）**：这个玩法在 macOS 社区已经火了几个月，有 3 个开源项目：

| 项目 | 平台 | 方案 |
|---|---|---|
| godarrenw/mi_remote_control | macOS | hidutil 重映射 + ATVV 语音 → BlackHole 虚拟声卡 → 豆包输入法 |
| fanxeon/mi-ao（米遥） | macOS | ATVV → whisper.cpp 本地转写 → Codex |
| nijez/open-voice-bridge | macOS | 最完整，Windows 版只是未验收的源码候选 |

**Windows 没有任何现成方案**——本项目填补了这个空白，
最终功能对齐 macOS 项目并超出（哑键救回、微信桥接是 macOS 项目没有的）。

## 1. 设备层摸底（不做任何假设，全部实测）

用 PowerShell + Python(winrt) 确认了关键事实：

- 按键走**标准 HID 键盘**通道；VID 2717 / PID 32B8；固件 2671；型号 RC003
- Windows 设备路径是 BTHLE 风格 `VID&012717_PID&32b8`（不是 USB 的下划线格式）
- **语音走 ATVV 私有 GATT 协议**（服务 AB5E0001-5A21-...，Windows 标成"小米厂商服务"
  但实际是 Google ATVV），系统不认它为麦克风，必须自己解码
- **返回键/音量±的 HID 报文被 Windows 驱动丢弃**（报文到了 WUDFHost 里的
  HidOverGatt 驱动，但 usage Back=0xF1 / 音量=0x80/0x81/0x7F 翻译不成键盘事件）

## 2. 按键引擎

- **Win32 Raw Input**（纯 ctypes）按 VID/PID 过滤，只认遥控器，物理键盘零影响
- 交互式学习模式 → GUI 可视化绑定（点击遥控器图上的键）
- 动作系统：SendInput 组合键 / 聚焦窗口 / 音量 / 粘贴文本 / 启动程序
- 遥控器按键 → VK 映射全部实测：方向=UP/DOWN/LEFT/RIGHT、OK=RETURN、
  语音键=F5（scan 0x3F）、TV=0xC0、电源=0xFF、主页=HOME、菜单=APPS

## 3. 语音链路（本项目技术含量最高的部分）

### ATVV 协议实现
按 mi-ao 项目的协议文档（同款固件 2671）实现：
```
BLE GATT 直连（winrt） → GET_CAPS 握手（0A 01 00 00 03 03）
→ MIC_OPEN（0C 00）→ 120 字节 ADPCM 帧流（AB5E0003 notify）
→ 松手（遥控器自报 00 02）→ MIC_CLOSE（0D 00）
→ IMA/DVI ADPCM 解码 → 16kHz PCM → WAV
```

### 本地 whisper 转写
- faster-whisper（RTX 4060 GPU，medium 模型），中文准确率 90%+
- **最大坑：用户 PowerShell 配置文件（starship/nvm）污染环境导致 ctranslate2 CUDA
  原生崩溃**（access violation，faulthandler 定位）→ 解法是**转写放干净环境子进程**
  （只传必要环境变量 + 强制 HF 离线 + 显式 UTF-8 解码，每个坑单独踩过）

### 微信语音模式（切换式桥接，最终架构）
目标：用微信输入法的语音（自动去语气词、整理语句）。

踩掉的三个坑：
1. **遥控器语音键 = F5 透传，按住期间会干扰微信组合热键检测**（实测复现）
   → 录音期间零注入，音频先缓冲
2. 按住式热键（Ctrl+Win）行不通 → 改用**切换式**（短击 Ctrl+Win+Shift
   开启持续语音，再短击结束）
3. 浮窗归属是**微信输入法 WeType 进程**（不是微信聊天客户端），
   其设置里可切麦克风到 CABLE Output

最终链路：
```
按住遥控器语音键说话（音频缓冲，零注入）
→ 松手 → 短击 Ctrl+Win+Shift（WeType 开始听 CABLE）
→ 0.45s → 开 VB-CABLE 流播放缓冲（16k→48k 重采样）
→ 播完 → 再短击 → WeType 识别（去语气词）→ 文字上屏
```

## 4. 哑键救回（返回/音量±）

移植自 GPL-3.0 项目 remote-bridge-hub（致谢）：
- **frida-gadget DLL（17.15.3，双 SHA-256 锁定官方发布物）**
  由提权 helper 用 LoadLibraryW 注入 WUDFHost
- Gadget 内 JS 钩 `NtDeviceIoControlFile`（IOCTL 0x80018483，9 字节输出 =
  被丢弃的按键报文），经 localhost:30685 推回主进程解码成按键边沿
- 护栏：注册表 HostPid 匹配 + wudfhost.exe 进程名校验 + 哈希校验
- 注意：frida-python 的 attach 被 WUDFHost 拒绝，必须用 Gadget 路线

## 6. 踩坑总集（后来者必读，价值最高）

### ctypes 四连坑（同一类问题踩四次！）
**所有返回 HANDLE/指针的 Win32 API 必须显式声明 `restype=c_void_p`**，
否则 64 位句柄被截断成 32 位：
1. HWND（WinError 1400）2. GetCurrentProcess（WinError 6）
3. GlobalLock（memmove 写 NULL 崩溃）4. GetClipboardData

### SendInput 结构体坑（让所有按键动作静默失效一个月）
`INPUT` union 必须含 MOUSEINPUT+KEYBDINPUT+HARDWAREINPUT 全部三种，
否则 sizeof(INPUT)=32≠40，SendInput **静默返回 0**（方向键走透传所以没暴露）。

### 其他高频坑
- Win32 消息循环必须在创建窗口的同一线程
- ShellExecuteW "runas" 提权会丢工作目录（helper 用绝对路径启动）
- subprocess 的 text=True 在中文 Windows 默认 GBK（必须显式 utf-8）
- 空字符串环境变量不能传给子进程（HF_HOME="" 定位失败）
- 外部 ShowWindow 硬显示 Qt 窗口 → 不重绘 → 空白（必须 Qt 亲自 show）
- QFileSystemWatcher 监听 TEMP 目录不触发（用轮询）
- `exe --silent` 参数要在 `__main__.main()` 登记，否则被当未知命令秒退
- 录制键对话框必须 exec()，构造后直接读属性永远是 None
